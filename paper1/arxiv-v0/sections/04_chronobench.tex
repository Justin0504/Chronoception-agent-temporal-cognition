\section{ChronoBench}
\label{sec:chronobench}

\textsc{ChronoBench} is the diagnostic benchmark we use to measure $\cce$ and its sub-components across the panel. The design philosophy is single-axis isolation: each instance loads exclusively on one of the three Times.

\paragraph{Capability taxonomy.}
The benchmark partitions chronoceptive capability into three axes, with three sub-capabilities each (Table~\ref{tab:capabilities}).

\paragraph{Two settings.}
Every instance is evaluated under two settings:
\begin{itemize}[leftmargin=*]
    \item Setting A (no-injection): system prompt = ``You are a helpful assistant.'' --- the framework's chronoception baseline.
    \item Setting B (with-injection): system prompt prepends \texttt{Current date and time: <ISO timestamp>} --- emulates the consumer web-chat harness behaviour documented in \S\ref{sec:injection-tell}.
\end{itemize}

\paragraph{Scale.}
We collect 30 trajectories per (model, capability, setting) cell. The full sweep reported in this paper is approximately 4{,}000 trajectories across all 9 capabilities, the 10-agent panel, and both settings.

\paragraph{Open-source serving.}
The Qwen2.5-7B agent is served via vLLM 0.6.4 on a single A40 GPU at the Yue Zhao lab, exposed via an OpenAI-compatible REST endpoint. Including an open-source model removes provider-side injection as a confound and demonstrates that the framework can be reproduced without API budgets.

\paragraph{Implementation.}
\textsc{ChronoBench} ships as a $\texttt{pip}$-installable Python package (\texttt{chronoception}) with a command-line interface, three backend adapters (OpenAI, Anthropic, OpenAI-compatible for vLLM/Ollama), and a metric library implementing $\parkinson$, $\CAR$, $\confab_{\text{retro}}$, $\confab_{\text{pro}}$, CI coverage, and the aggregate $\cce$. Full reproducibility specification appears in Appendix~\ref{app:annotation-protocol}.
